# مرحلة 4 — محرك سير العمل (المهام والإسناد) + ربط الواجهة بالخلفية

## ما أُنجز

### الخلفية (NestJS) — وحدة Tasks كاملة
| المسار | الفعل | منطق الحماية |
|---|---|---|
| `POST /tasks` | إنشاء مهمة | `TASKS:CREATE`؛ إسناد افتراضي للمستخدم الحالي إن لم يُحدَّد معيّن |
| `GET /tasks` | قائمة المهام | `TASKS:READ`؛ النطاق: الكل (بارِع/كاتب) أو المسند/المنشِئ فقط |
| `PATCH /tasks/:id/complete` | إتمام مهمة | `TASKS:UPDATE`؛ لا يتمّ من ليس مسندًا إليه إلا من بصلاحية النطاق الكامل |

كل عملية تُسجَّل في AuditLog.

### الواجهة (Next.js) — ربط حقيقي بالخلفية
- **جدول الملفات** أصبح يجلب من `GET /cases` فعليًا (بدل Mock) مع حالة تحميل ورسائل خطأ.
- **نموذج فتح الملف** يرسل إلى `POST /cases` عند الإتمام، ويحدّث الجدول بعد النجاح.
- الصفحة الهبوط أُضيفت على `/` (أصلية، عربية RTL، توجّه إلى `/login`).

## حلّ خطير
تعرّض `package.json` لترقية تلقائية إلى **Next 16 + React 19** (غير متوافقة مع antd 5 وتُنهار بالذاكرة). عولجت بإعادة تثبيت نظيف:
`next 14.2.35` + `react 18.3.1` + `antd 5.21.6` (مثبتة بشكل صارم بلا `^`).

## التحقق
- الخلفية: `npx tsc --noEmit` → **0 أخطاء** (مع وحدة tasks).
- الواجهة: `npx next build` → **8 صفحات تُنتج بنجاح**.
- تشغيل فعلي: `landing:200` · `login:200` · `cases:200`.

## المسارات النهائية
| مسار | الصفحة |
|---|---|
| `/` | صفحة الهبوط (عامة) |
| `/login` | تسجيل الدخول |
| `/cases` `/hearings` `/tasks` | الوحدات الداخلية (تجلب من الخلفية) |

## تنبيه
النظام يعمل من طرف لآخر **بمجرد تشغيل PostgreSQL**:
```bash
cd sgba-erp && docker compose up -d
cd backend && npx prisma migrate dev --name phase4 && npm run prisma:seed && npm run start:dev
```
