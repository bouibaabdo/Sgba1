# معمارية النظام — SGBA-ERP

## 1. ما أكدناه من تحليل موقع sgba.ma الأصلي

من فحص DOM الصفحة العامة (2026-10-28):

- **الواجهة عربية أولًا و RTL** (`<html lang="ar" dir="rtl">`) مع خط **Cairo** للعربية و **Open Sans** للاتينية → قرار ملزم: `ar` هي اللغة الافتراضية، و `fr` لغة ثانية كاملة.
- ادعاء "دعم متعدد اللغات" في صفحتهم التسويقية → كل جدول مرجعي في مخططنا يحمل حقولًا ثنائية (`nameAr` / `nameFr`).
- مسارات التطبيق الداخلي: `/app/login/` و `/app/request-account/` (الشرطة المائلة الختامية ونمط `/static/` يوحي بخلفية Django/Flask — لا يهم معماريًا؛ سنبني بمعمارية حديثة).
- مكدس صفحتهم التسويقية (jQuery + Tailwind 2 + Swiper) **ليس** مكدس التطبيق — تجاهلناه.
- وظائف مذكورة في تسويقهم نؤطرها كمتطلبات: لوحة قيادة (القضايا + التكاليف)، تقويم الجلسات، تقارير نتائج الجلسات، شاشة تفاصيل الزبون، إدارة التكاليف.

## 2. المكدس المختار

| الطبقة | التقنية | المسوغ |
|---|---|---|
| Frontend | Next.js 16 (App Router) + **Ant Design 5** (وضع RTL) | أنضج جداول بيانات (فرز/فلترة/Row selection/Bulk) ونماذج متعددة الخطوات |
| i18n | next-intl — `ar` (RTL, Cairo) افتراضي + `fr` | متطلب مغربي أساسي |
| Backend | NestJS 12 + Express 5 + Prisma ORM | Guards/Decorators طبيعية لـ RBAC صارم |
| قاعدة البيانات | PostgreSQL 16 | FTS للبحث الشامل، JSONB للـ audit، أقسام زمنية للأرشيف لاحقًا |
| الملفات (مرحلة 5) | MinIO / S3-compatible | DMS |
| المصادقة | JWT: access 15min + refresh 7 أيام (تدوير)، bcrypt(12) | |

## 3. نمط المستودع

مستودع أحادي يضم `backend/` و`web/`، ويستخدم أوامر الجذر لتشغيل الخدمتين من دون تفعيل npm workspaces حتى الآن:

```
sgba-erp/
├── backend/        # NestJS API
├── web/            # Next.js RTL
└── packages/shared/  # كتالوج الصلاحيات + الأنواع المشتركة (يُستخرج لاحقًا من src/rbac)
```

## 4. طبقات الأمان

1. **خط الدفاع الأول — `PermissionsGuard`**: كل مسار مغيّر للحالة يعلن صلاحياته بـ `@RequirePermissions(...)`؛ الوصول بلا صلاحية = `403 INSUFFICIENT_PERMISSION` مع ذكر الصلاحية الناقصة.
2. **نطاقات الصلاحية (Scope)**: `OWN ⊂ ASSIGNED ⊂ ALL` — نفس الصلاحية تُمنح بنطاق مختلف لكل دور، والفلترة على مستوى الصف تُطبق في الـ services عبر `RbacService`.
3. **حظر مالي للكاتب والتلميذ**: لا يوجد أي إذن `FINANCE:*` في تعريفي هذين الدورين إطلاقًا — حماية بالتصميم لا بالاستثناء.
4. **Audit Log**: كل عملية كتابة حساسة تُسجل (من، ماذا، متى، IP) — جدول `AuditLog`.
5. **حذف ناعم**: الأدوار والملفات لا تُحذف فيزيائيًا (تُؤرشف/تُعطّل) — قاعدة ERP قياسية.

## 5. قرارات افتراضية (معلقة على تأكيدك — لا تعيق العمل)

- الاستضافة: سيرفر المكتب (Docker Compose) — قابل للتحويل إلى Cloud.
- مكتب واحد (Single-tenant)؛ مخطط `courtId/internalRef` لا يمنع إضافة `firmId` لاحقًا للـ Multi-tenant.
- الفريق: TypeScript موحد أمامًا وخلفًا.

## 6. الأرشفة المادية (متطلب صريح)

على جدول `Case`: `archiveCabinet` (الخزانة)، `archiveShelf` (الرف)، `archiveBox` (العلبة)، `archiveNotes`، `archivedAt` — مع فهرسة بحث سريعة، بحيث يكتب المحامي رقم الملف فيبحث فتحصل على "خزانة B / رف 3 / علبة 12".
